# W1 report: S3 / MinIO version source

## 1. What I did and decided
Continued the partial files. `s3.py`, `seed_minio.py`, the CLI and the compose service were already complete and
worked, so I did not change them. I added the golden data and both test files, then checked live.

Decision: versions come from native S3 object versions (bucket versioning), not from key naming.
Why: that is what a versioned bucket really is, so no naming rule is forced on the users' files, and the doc_id is
just the key without its extension (stable). A second layout, `--layout folders` (`<doc>/v<N>[_date].<ext>`),
covers buckets without versioning.
- Order = the order S3 keeps per key (oldest = 1), not LastModified (quick uploads can share a timestamp).
- Label = user metadata `version`, else `v<n>`. Same label twice: the newest wins (re-upload).
- Date = metadata `effective-date`, else LastModified in UTC. sync still prefers an "Effective date:" line in the text.
- Delete marker on top: doc is deleted, not produced, listed in `deleted_docs` (CLI prints it). Undelete restores it.
- Two live keys with one doc_id (policy.md + policy.pdf) is an error.
Seeded doc: `it-security-policy` (Fabrikam IT Security Policy) v1.0 / v1.1 / v2.0, one key, 3 object versions.
