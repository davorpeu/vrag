# W2 report: retrieval eval + reranker

## 1. What I did and decided
- Continued the partial files. The cases check clean (89 cases on vrag-eval, 0 problems). Model files were already in data/models (88 MB, gitignored). fastembed 0.9.1 was already installed, so I installed nothing.
- answer.py now builds its filters with store.latest_filters / version_filters / compare_filters (the same helpers the eval uses). It calls store.hybrid_search, which follows `settings.rerank`. So the reranker is wired in only behind the setting (the router's top-doc check and the compare ranking use it too when it is on).
- Reranker: cross-encoder Xenova/ms-marco-MiniLM-L-6-v2 through fastembed (ONNX, CPU, no torch). It reorders the top 20 fused hits. If the model cannot load or scoring fails, it logs one warning and keeps the search order.
- **Default: `RERANK=false`.** It wins on quality (below), but costs about +0.8 GB RAM and about 1.5 s per search. The PC has about 0.5 GB free, so turning it on by default risks swapping. To make it the default, change `rerank: bool = False` in config.py to True (or set RERANK=true in .env).
- I kept rerank_candidates = 20. With 10 it is faster but worse (see below).

## 3. Results (index vrag-eval, 89 cases, top 20 candidates reordered)
| mode | R@1 | R@3 | R@6 | MRR | doc@1 (53 q) | p50 ms | p95 ms |

| bm25 | 0.596 | 0.753 | 0.831 | 0.690 | 0.717 | 20.8 | 31.8 |

- Rerank vs hybrid: recall@6 +0.067, MRR +0.124. Biggest gain on paraphrase questions (R@6 0.50 -> 0.89, MRR 0.42 -> 0.87).
- Cost: cross-encoder step alone p50 1422 ms, p95 2607 ms; first call (model load) 2471 ms; process RAM 96 MB -> 897 MB (about +800 MB, measured as working set).
- With 10 candidates: R@1 0.820, R@6 0.921, MRR 0.883, p50 594 ms, RAM 611 MB. Faster and smaller, but worse than 20.
- Tests: tests/test_rerank.py + tests/test_store.py = 15 pass (offline). Full fast suite: 168 passed, 42 deselected.

## 6. Follow-up ideas
1. **kNN alone beats the current hybrid** on this eval (R@6 0.978 vs 0.899, doc@1 0.981 vs 0.830) and costs no RAM. The BM25 side hurts on paraphrase questions because it ranks semver chunks for words like "bring it back". Try a weighted RRF (kNN weight above BM25) or kNN-only for the router's doc check. This is likely a bigger and free win than the reranker.
2. Try a smaller or quantised cross-encoder, or 10-15 candidates, if RAM matters.
3. Grow the cases from real questions in the Langfuse traces once it runs again.
