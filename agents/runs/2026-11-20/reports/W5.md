# W5 report: compare answer fix + weighted RRF fusion

## 1. What I did and decided
- **mentions_change (answer.py).** A modified change is now identified by its changed value. If the changed
  run has a number ("1 year" -> "2 years"), that exact phrase must appear in the answer (word-boundary match
  on normalised text). Before, shared words ("years") counted as covered. A first version of the fix
  (a bare number like "2" in the answer) still failed `compare-retention-labels`, because the answer said
  "section 2 Customer Data" and "Change 1". Phrase matching fixed it. Changes without numbers still use the
  changed key words; added/removed clauses are unchanged.
- **Weighted RRF (store.py).** `_rrf(..., weights)`, new `fuse(bm25, knn, w_bm25, w_knn, k)`; `hybrid_search`
  uses `settings.rrf_bm25_weight` / `rrf_knn_weight`. Settings in config.py and .env.example.
- **Default: BM25 1.0 : kNN 20.0 (rrf_k 60).** Chosen from the sweep below: it ties kNN-only on R@6 (0.978), has
  the best doc@1 (1.000, kNN-only 0.981), and is on a plateau (50 gives the same R@6 and MRR). I picked
  the low end of the plateau so BM25 still breaks ties for exact keywords. kNN-only is not used: BM25 adds
  nothing on keyword cases but also costs nothing at 1:20, and weight 0 would drop BM25 completely.
- **activity_index (W6 request):** `Settings.activity_index = "vrag-activity"`, `ACTIVITY_INDEX=vrag-activity`
  in .env.example, `activity.index_name()` returns `get_settings().activity_index`.
